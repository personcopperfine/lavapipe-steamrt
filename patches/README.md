# lavapipe fork patch series

Versioned local patches applied on top of the Mesa release tag.

* **Base:** the Mesa tag the release is named after (`MESA_TRACK` in `../track.env`,
  currently `mesa-26.3.*`). Originally written against main@`d289726`
  (26.3.0-devel); 0008 rebased onto `mesa-26.3.0-rc3`.
* Patches are plain `git diff` output, applied with `git apply -p1` in `sort` order.
* Naming: `NNNN-short-name.patch`.

## Verifying the fork-0002 UUID seed in the built ICD

The seed literal is `"lvp-cs2-fork-0003:" PACKAGE_VERSION` (19 chars before
concatenation), but `memcpy(uuid, seed, MIN2(strlen(seed), VK_UUID_SIZE))`
reads at most 16 bytes. GCC/Clang **truncate the string literal to 16 bytes**
in `.rodata`, so:

```bash
strings -a libvulkan_lvp.so | grep lvp-cs2-fork
# → "lvp-cs2-fork-000Mesa 26.3.0-devel (git-d289726f25) (LLVM 19.1.7)"
```

The visible marker is `lvp-cs2-fork-000` + the Mesa version string — **not**
`lvp-cs2-fork-0003`. This is expected and correct: the runtime UUID is derived
from the first 16 bytes of the seed, which is stable across builds. Do not
treat a missing `...0003` in `strings` output as a stale build; verify the
source instead (the Dockerfile's patch step greps for `lvp-cs2-fork-0003:` in
`lvp_device.c` and fails the build if absent).
| `0006-lvp-subgroup32.patch` | G4 fix: advertise `subgroupSize == minSubgroupSize == maxSubgroupSize == 32` (env `LVP_ADVERTISED_SUBGROUP_SIZE`, default 32; `=8` restores the old behaviour as the A/B control). CS2's RenderSystem drops every compute shader declaring `requiredSubgroupSize=32` when the ICD advertises less — 258 drops per boot (cull_instanced_meshes, compute_tile_cullbits, cs_parallel_sort_onesweep). The old value was `lp_native_vector_width/32` = 8; a true 32-lane subgroup is unreachable because gallivm's vector infrastructure caps at 512-bit vectors (`LP_MAX_VECTOR_WIDTH`, 16 lanes), so this is the GOALS G4.2 "recorded inconsistency" variant: advertise 32, execute at 8 lanes, and validate the cull shaders' output empirically by A/B frame comparison (t30, `docker/evidence/20260925-0148-` vs the post-0006 run). `tests/contract/t13_subgroups.sh` asserts the new contract; `LVP_REQUIRE_SUBGROUP32=1` is the hard gate. | `src/gallium/frontends/lavapipe/lvp_device.c` (`lvp_subgroup_size` + the three property sites) |
| `0007-llvmpipe-bptc-block-cache.patch` | G7 D6 throughput: gallivm has no vector BPTC decode, so every BC7/BC6H texel called the scalar C fetch, which re-decodes the block header + endpoints per texel (BC7 is 68% of shipped mip0 texels). Adds a per-thread cache of fully decoded 4x4 blocks (1024 BC7 unorm slots + 256 BC6H float slots, ~320 KB/thread, calloc'd lazily, keyed by block address, epoch-invalidated at `rasterize_scene`, each compute tpool task and `llvmpipe_draw_vbo`) and routes `fetch_rgba_8unorm`/`fetch_rgba` for the four BPTC formats through it. Env `LP_BPTC` bitmask: 1 = cache, 2 = routing, default 3; `LP_BPTC=0` is byte-identical to stock (A/B control). lvpfill: BC7 sample 5.0 → 40 Mpx/s, BC7 sRGB 5.7 → 42, BC6H 5.7 → 32, output byte-identical for BC7/BC7 sRGB/BC6H u+s/BC1. | `0008-lvp-descriptor-pool-limit.patch` | Crash fix + loop-rate prerequisite. Stock lavapipe ignored `VkDescriptorPoolCreateInfo::maxSets`, so `vkAllocateDescriptorSets` never returned `VK_ERROR_OUT_OF_POOL_MEMORY`; CS2 rotates its 27 pools (maxSets 1024) only on that error, so it never reset them and live sets grew ~500/frame. Every set owns one memfd `mmap`, so the process hit `vm.max_map_count` (1048576), `mmap` returned ENOMEM and `lvp_descriptor_set_create` memset `MAP_FAILED` → SIGSEGV on `VKRenderThread` (~10 s in-game with rendering skipped, roughly 6–8 min projected with normal rendering; gdb: `client/evidence/20261002-1923-map-frameskip-all-cs2gdb`). Enforcing maxSets (env `LVP_POOL_LIMIT=0` = old behaviour) bounds live sets to ~9–17k. The resulting ~50k mmap/munmap per second capped CS2's game loop at ~45 Hz, so freed set memory is recycled through a per-device FIFO per page count (1–16 pages), reused only after `LVP_DSET_CACHE_DELAY` (default 16384) newer frees: **LIFO reuse corrupted textures** (`20261002-2001-map-render-poolfix`) because CS2 resets a pool while queued work still reads its sets. `LVP_DSET_CACHE=0` disables recycling. Results: rendering skipped 45 → 210–230 Hz loop (`20261002-2025-map-frameskip-all-fifocache`); normal render frames match the 0007 baseline at 3.2–5 presents/s (`20261002-2019-map-render-fifocache`). The delay is a heuristic, not a fence-based quarantine. | `src/gallium/frontends/lavapipe/lvp_descriptor_set.c`, `lvp_device.c`, `lvp_private.h` |
